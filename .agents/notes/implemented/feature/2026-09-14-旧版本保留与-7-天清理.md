# Agent Note: 旧版本保留与 7 天清理

Status: implemented

## Problem

远程目录中的历史版本会持续累积，项目列表和版本列表缺少清理入口。仅按目录修改时间判断旧版本会把元数据写入、复制或共享目录行为误当成上传时间。

## Decision

`src/shared/version-retention.ts` 统一定义 7 天保留窗口：版本日期优先使用 `.version.json.uploadedAt`，缺失或无效时使用扫描产生的目录 `createdAt`，两种时间都无效的版本不进入自动清理。`version:scan-summaries` 汇总每个远程目录的总数、近期数、过期版本、未知日期数和最新版本，并按最多 3 个目录并发扫描。首页在项目超过 10 个版本时显示提醒，研发可一键删除过期版本；当前下载版本不进入默认清理集合。项目详情页默认只显示近 7 天版本，可切换到全部。

## Alternatives considered

- **仅按目录 `mtime` 清理**：文件和元数据写入会改变时间，无法稳定表达上传时间。
- **在前端分别实现过滤和清理规则**：首页与详情页容易产生不同的边界判断。
- **按数量保留固定个数**：不能满足“删除 7 天前版本”的业务口径，也会删除仍在使用的新版本。
- **在渲染层并发扫描全部项目**：页面需要重复处理网络目录错误、超时和并发控制。

## Consequences

版本日期和清理规则只有一处实现，并受单元测试覆盖。首页增加一次异步摘要扫描，但不会阻塞项目列表渲染。没有有效日期的版本继续显示但不会自动清理；当前下载版本需要研发显式进行普通删除。
