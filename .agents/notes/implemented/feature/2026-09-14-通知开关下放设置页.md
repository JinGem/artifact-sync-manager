# Agent Note: 通知开关下放设置页

Status: implemented

## Problem

系统通知和应用内通知分散在主进程与多个组件中，用户无法关闭不需要的提醒。每个触发点独立判断会遗漏设置变化，也无法形成一致的通知行为。

## Decision

`AppSettings.notifications` 保存 `system` 和 `inApp` 两个布尔值，默认均为开启。主进程通过 `src/main/notification.ts` 统一发送系统通知并读取 `system`；渲染层通过 `src/renderer/src/services/notification.ts` 统一发送应用内通知并读取 `inApp`。设置页提供两个开关，通过 `config:save-notification-settings` 立即保存。

## Alternatives considered

- **在每个通知调用点分别读取设置**：重复判断逻辑，新增通知时容易漏掉开关。
- **只提供总开关**：用户无法在保留应用内结果提示的同时关闭 Windows 通知。
- **把开关放在首页或标题栏**：通知是低频偏好设置，放在设置页更符合使用频率。

## Consequences

所有新增通知必须走统一服务。应用内结果通知和远程变化通知共用 `inApp`；系统通知只由主进程服务发送，并受 `system` 控制。
