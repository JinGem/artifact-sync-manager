# Agent Note: 项目采用一层组模型

Status: implemented

## Problem

项目列表只有扁平数组，项目数量增加后无法按团队、产品线或环境组织。把项目数组嵌套进组会改变项目查询、Watcher、最近项目和导入导出的访问方式。

## Decision

`AppState.groups` 保存组 ID、名称和时间戳，`ProjectConfig.groupId` 保存项目归属，未组项目使用 `null`。组名称大小写不敏感唯一，项目名称继续全局唯一。首页按 `groups` 数组顺序渲染组区块，未组项目进入固定区块。项目配置弹窗支持选择已有组或输入新组名称，输入的新名称与项目创建在同一次 `saveProject` 写入中完成。配置导入导出处理 `groupId`；删除组只把相关项目设为未组，不删除项目或远程文件。首页组区块可以折叠，颜色用于组标题和项目所属组选择器。

## Alternatives considered

- **在 `ProjectConfig` 上只保存组名称**：重命名需要批量修改项目，同名和冲突处理也不稳定。
- **嵌套 `groups[].projects[]`**：项目查询、Watcher 同步和导入导出都要处理嵌套结构，收益仅为展示层级。
- **支持任意深度树**：当前需求只有一层，递归树增加排序、移动和循环引用处理。

## Consequences

项目列表渲染和配置表单增加组选择，主进程保存项目时校验组存在性。组存储在本机 `app-state.json`，不会自动同步到其他电脑；通过配置导出和导入传递。现有配置缺少 `groups` 字段时按空列表处理，项目归入未组。
