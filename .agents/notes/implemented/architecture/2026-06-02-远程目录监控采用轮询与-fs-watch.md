# Agent Note: 远程目录监控采用轮询与 fs.watch

Status: implemented

## Problem

远程目录可能位于 SMB 共享或本地磁盘，其他开发者会在应用外上传和删除版本。网络共享对文件系统事件的可靠性不一致，单纯等待用户刷新会让版本列表和通知滞后。

## Decision

`src/main/watch/directory-watcher.ts` 的 `watcherService` 对每个规范化远程目录执行 30 秒轮询，并在目录支持时同时注册非递归 `fs.watch` 以缩短响应时间。第一次扫描只建立版本快照，后续比较 `vX.Y.Z` 目录集合。同一目录只保存一个 watcher，多个项目通过 `projectIds` 和 `projectNames` 共享事件。

## Alternatives considered

- **只依赖 `fs.watch`**：SMB 和休眠恢复场景可能丢失事件。
- **只依赖轮询**：实现简单，但变化最多延迟一个轮询周期，且每次都要扫描。
- **只提供手动刷新**：用户无法可靠获知其他终端产生的版本变化。

## Consequences

网络共享不可用时只跳过当前轮询；目录恢复后继续比较快照。变化检测最多延迟 30 秒，应用启动后首个快照不产生通知。主进程会过滤本进程正在上传或删除的版本，避免重复提醒。
