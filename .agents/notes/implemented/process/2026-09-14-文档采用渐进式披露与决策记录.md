# Agent Note: 文档采用渐进式披露与决策记录

Status: implemented

## Problem

根说明文件同时承载项目介绍、架构、代码风格、提交规范和决策历史，任务越多，代理越难判断应该读取哪些事实。架构内容与 README、CONTEXT 重复，设计原因只存在于提交信息或个人记忆中。

## Decision

仓库使用根 [AGENTS.md](../../../../AGENTS.md) 作为任务到文档的地图，详细文档标准放在 [docs/AGENTS.md](../../../../docs/AGENTS.md)，系统事实放在 [docs/architecture.md](../../../../docs/architecture.md)，模块事实放在源码目录 README，决策原因放在本目录。`scripts/verify-docs.mjs` 检查链接、预算和笔记格式，Husky `pre-commit` 运行文档快速检查。

## Alternatives considered

- **继续维护单一大型 AGENTS.md**：每次任务都加载无关规则，重复内容难以同步。
- **让 README 同时承担使用说明和架构参考**：用户入口与代理上下文目标不同，容易继续膨胀。
- **只依赖人工评审**：没有机械检查时，断链、超预算和笔记缺章节不会稳定被发现。
- **把决策理由写进现状文档**：会混合历史与当前事实，修改实现时难以区分可变事实和既有取舍。

## Consequences

任务开始前必须经过根地图定位文档，任务结束前必须检查 doc-sync 和决策记录并运行 `npm run verify:docs`。文档数量增加，但每个事实有明确归属；脚本、Husky 钩子和评审共同防止文档再次漂移。
