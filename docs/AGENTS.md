# AGENTS.md — 文档标准

> 本文件定义文档层级、写作规则和机械校验。改 Markdown 前先读本文；校验入口为 `npm run verify:docs`。

## 层级地图（一事实一归属）

| 层级       | 位置                                                  | 职责                        | 不放                 |
| ---------- | ----------------------------------------------------- | --------------------------- | -------------------- |
| 根指令     | [AGENTS.md](../AGENTS.md)                             | 任务阅读地图与硬性规则      | 故事、示例、步骤     |
| 文档标准   | 本文件                                                | 层级、写作、审计、预算      | 产品与运行时事实     |
| 产品参考   | [docs/产品文档.md](产品文档.md)                       | 场景、范围、边界、业务规则  | 实现结构、决策理由   |
| 工程上下文 | [CONTEXT.md](../CONTEXT.md)                           | 技术约定、验证、提交和发版  | 需求复述、模块细节   |
| 系统地图   | [docs/architecture.md](architecture.md)               | 进程、IPC、持久化、目录职责 | 类型、组件、决策理由 |
| 模块文档   | 源码目录内的 `README.md`                              | 模块行为、限制和验证        | 跨模块架构、产品需求 |
| 决策记录   | [.agents/notes/README.md](../.agents/notes/README.md) | 原因、备选方案和后果        | 当前行为、计划       |
| 操作手册   | `docs/cookbook/*.md`                                  | 编号步骤和可观察结果        | 设计理由             |
| 事故记录   | `docs/postmortem/*.md`                                | 时间线、证据、原因和预防    | 教学序列             |

文档只详述自己的主题，对下级只写目的、职责和高层行为。每篇文档必须明确是教程或参考；教程按前置知识排序，参考只描述查询范围与当前行为。

## 写作规则

- **doc-sync**：代码行为、路径、命令或限制变化时，在同一提交更新受影响的模块 README、系统地图或产品文档。
- **当前状态**：现状文档只写现在是什么；历史与废弃方案写入决策记录，计划写入 [TODO.md](../TODO.md)。
- **fact-check**：命令、路径、默认值、错误和平台行为必须读源码或实际运行验证；无法验证就删除或标注 `(未验证，验证负责人：姓名)`。
- **一事实一归属**：同一事实只在一处详述，其他文档链接到拥有者，禁止复制后各自维护。
- **具体散文**：直呼文件和函数；保留参与者、动作、条件、时序、情态和后果；删除形容词堆叠及推理过程。
- **UI 文案属于行为**：按钮、提示和错误文案的改动必须核查相关页面和交互。

## 审计清单

写或审文档时逐条检查，命中即修正：

- 同一事实是否在多个文档重复。
- 是否出现“之前、现在、已改为、未来将、计划中”等历史或状态词。
- 是否手抄目录、配置项、测试清单或类型定义。
- 是否记录逐步实现过程、推理路径或被否决的局部方案。
- 是否出现未验证的项目行为。

## 交叉链接与决策

仓库内引用使用相对 Markdown 链接，不使用裸文件名或“见上文”。移动或重命名文档时，同一提交更新所有入链。非平凡取舍必须按 [.agents/notes/README.md](../.agents/notes/README.md) 新增或更新决策记录；机械改动豁免。任务收尾时更新受影响文档，运行 `npm run verify:docs`，代码改动再运行 test、typecheck 与 build，并在交付说明中列出结果。

## 预算与格式

预算清单见 [scripts/doc-budgets.json](../scripts/doc-budgets.json)。超限时先迁移再精简；提高上限需说明理由。正文用简体中文，每段一行，代码与源码一致。
