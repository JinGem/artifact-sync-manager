# Artifact Sync Manager 产品文档

> 合并自：需求文档、产品设计与技术方案、目录结构与开发计划

---

## 第一部分：需求规格

### 1. 项目概述

Artifact Sync Manager 是一个面向公司内网开发者的 Windows 桌面工具，用于管理项目产物的上传、下载和版本记录。

核心目标不是做通用网盘或完整发布平台，而是解决以下实际问题：
1. 项目产物通过手工复制、粘贴、覆盖管理，操作繁琐
2. 版本记录不清晰，难以回溯
3. 缺少上传/下载进度反馈
4. 缺少稳定的排除规则

### 2. 目标用户与场景

目标用户：公司内网开发者。

典型场景：
1. 将本地构建产物上传到远程目录
2. 下载某个历史版本用于测试、部署或回滚
3. 通过规则过滤不需要上传/下载的文件

### 3. 系统边界

- **纯桌面端**：桌面应用直接访问本地目录和远程目录
- **无独立后端服务、无数据库、无账号系统**
- 本质上是带版本管理能力的内网文件同步工具

### 4. 运行环境

- 支持系统：Windows 10、Windows 11
- 远程存储：内网服务器本地磁盘或共享路径
- 地址示例：`\\192.168.1.88\home\projects`、`D:\home\test`

### 5. 功能范围

#### 第一版必须实现
1. 首次启动填写操作者名称
2. 项目创建与配置管理
3. 上传单个文件或整个文件夹
4. 下载指定版本内容
5. 版本信息管理
6. 上传规则与下载规则分别配置
7. 上传前扫描并预览待上传文件列表
8. 上传时版本号自动递进：单选（新增→minor / 修复→patch）+ 勾选（破坏性变动→major），首次默认 v1.0.0
9. 上传和下载任务进度展示
10. 任务取消
11. 错误提示和基础错误码
12. 配置导入与导出
13. 单个版本删除
14. 下载前可选择清空目标目录
15. **系统托盘**：关闭窗口到托盘，单实例锁，右键菜单
16. **远程目录监控**：自动检测版本变化并弹出系统通知
17. **应用图标**：窗口/任务栏/托盘统一哆啦A梦图标

#### 第一版明确不做
1. 独立后端服务
2. 用户登录、权限系统、密码校验
3. 消息通知与版本更新通知
4. 文件完整性自动校验
5. 历史任务长期留存
6. 默认规则模板
7. 历史版本差异对比
8. 审计日志
9. 自动增量同步
10. 部分文件下载

### 6. 操作者规则

- 首次启动必须填写操作者名称
- 操作者名称不能为空、不要求唯一
- 保存在本地配置中，后续可在设置页修改
- 上传版本时自动记录当前操作者名称

### 7. 项目模型

一个项目包含：项目名称、远程目录、上传本地路径、下载本地路径、上传规则、下载规则、版本列表信息。

约束：
- 项目名称唯一；远程目录不能为空
- 上传/下载路径允许按场景单独配置
- 同一个本地/远程目录允许被多个项目复用
- 删除项目配置时不删除远程文件
- 可以删除单个版本文件及其版本记录

### 8. 版本模型

一个版本包含：版本号、版本说明、创建时间、上传人、文件总大小、远程存储路径。

规则：
- 版本号采用语义化格式（如 `v1.0.0`）
- 同一项目内版本号唯一
- 默认自动生成版本号，用户可修改
- 版本说明非必填
- 第一版不允许草稿版本

### 9. 版本状态

用于系统流程控制的版本状态：
- `uploading` / `success` / `failed` / `downloading`

补充规则：
- 上传失败不保留版本记录
- 下载失败不保留历史任务记录
- 成功版本不允许再次覆盖上传
- 取消上传时删除已上传内容和版本信息
- 取消下载时提示用户本地文件可能已被部分修改

### 10. 规则系统

- 上传规则与下载规则分别配置，项目级配置
- 规则语法完全参考 `.gitignore`
- 由于 `.gitignore` 本身支持排除与反向包含，不再额外设计白名单/黑名单两套独立语义
- 规则修改不影响历史版本内容

### 11. 任务进度展示

展示：总进度百分比、当前处理文件名、已传输文件数、总文件数、传输速度、成功/失败状态。

补充规则：
- 需要独立的任务中心页面
- 任务完成后自动清除，不保留长期历史记录
- 失败任务允许重试
- 程序关闭后不保留任务记录

### 12. 错误处理

需要处理的错误场景：远程目录不可访问、本地目录不存在、权限不足、文件被占用、网络中断、磁盘空间不足、版本号重复。

- 以弹窗方式提示用户
- 需要基础错误码，便于定位问题

### 13. 本地配置

保存内容：操作者名称、最近使用项目、项目列表。

补充规则：
- 允许配置导入和导出
- 导入时若发现重复或冲突，跳过并提示结果统计
- 卸载软件后保留本地配置
- 若配置损坏，提示配置异常即可

### 14. 已明确决策

- 下载目录不是必须固定配置，允许按项目配置也允许临时选择
- 第一版不允许只下载版本中的部分文件
- 允许删除单个版本，同时删除远程目录中对应版本文件和版本信息
- 项目配置可以只配置上传路径或只配置下载路径
- 前端使用 Tailwind CSS + Element Plus（基于 Vue 3）

## 第二部分：技术方案

### 1. 技术选型

- 桌面端：Electron
- 前端框架：Vue 3
- 语言：TypeScript
- 样式：Tailwind CSS + Element Plus
- 状态管理：Pinia
- 路由：Vue Router
- 构建方案：Vite（electron-vite）
- 本地配置存储：JSON 文件

### 2. 不建议引入的内容

1. 独立 Node.js 服务
2. SQLite 或其他数据库
3. 复杂 ORM
4. Web 后台
5. 自动升级系统

原因：第一版核心工作是本地文件操作、路径配置、规则过滤、进度管理和版本目录组织。

### 3. 数据持久化方案

建议拆分为：
- `settings.json`：操作者名称、最近使用项目
- `projects.json`：项目配置列表

版本信息通过扫描远程目录和本地项目配置生成。

### 4. 版本目录组织

```
<remote-root>/
  <version>/
    .version.json                ← 版本元数据（含 sourceFolderName）
    <source-folder-name>/        ← 上传源文件夹名
      ...
```

例如：`\Remote\v1.0.0\win-test\`

优点：结构直观、易于手工排查、不依赖数据库、符合桌面直连方案。

### 5. 错误码系统

8 个基础错误码：
- `PATH_NOT_FOUND`
- `REMOTE_NOT_ACCESSIBLE`
- `PERMISSION_DENIED`
- `FILE_LOCKED`
- `NETWORK_INTERRUPTED`
- `DISK_FULL`
- `VERSION_DUPLICATED`
- `TASK_CANCELLED`

### 6. 关键交互原则

1. 上传、下载、删除都必须给出明确确认
2. 远程路径和本地路径必须可见
3. 高风险操作提示后果
4. 默认流程偏保守，避免静默覆盖
5. 上传路径和下载路径允许分开配置，界面上明确区分

## 第三部分：开发计划

### 推荐目录结构

```
artifact-sync-manager/
  docs/
  src/
    main/           ← 文件系统、任务执行、配置、IPC
      app/
      fs/
      task/
      config/
      version/
      project/
      ipc/
      utils/
    preload/        ← 安全桥接
    renderer/src/   ← 界面、表单、状态管理、任务展示
      components/
      views/
      stores/
      router/
      services/
      types/
      utils/
      styles/
  scripts/
  package.json
  tsconfig.json
  electron.vite.config.ts
```

### 开发阶段

#### 阶段 1：项目初始化
- 初始化 Electron + Vue 3 + TypeScript + Tailwind CSS + Element Plus
- 跑通三进程（main/preload/renderer）
- 建立基础路由和页面壳子

#### 阶段 2：本地配置能力
- 首次启动录入操作者名称
- 保存和读取本地配置
- 项目配置列表 CRUD
- 上传/下载路径分开配置

#### 阶段 3：项目与版本浏览
- 项目列表页、项目详情页
- 远程目录版本扫描
- 版本信息展示、单个版本删除

#### 阶段 4：上传能力
- 文件选择、规则过滤、扫描预览
- 上传进度展示、取消上传

#### 阶段 5：下载能力
- 版本选择、目标目录、冲突处理
- 下载进度展示、取消下载

#### 阶段 6：任务中心与错误处理
- 独立任务中心、错误弹窗、基础错误码
- 失败任务重试

#### 阶段 7：收尾
- 设置页、配置导入导出
- 打包 Windows 应用
- 补充文档和使用说明

### 实施顺序原则

建议严格按以下顺序推进：
1. 项目配置和操作者配置
2. 版本列表浏览
3. 上传
4. 下载
5. 任务中心和设置页

上传下载最复杂，应建立在配置、路径、规则和项目模型都稳定之后再动手。
